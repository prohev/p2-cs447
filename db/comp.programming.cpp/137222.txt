<!-- SC_OFF --><div class="md"><p>I am currently working with a C API which will fill a given buffer with bytes representing a one of two possible POD types. And then returns the size of the object that was written into the buffer. So we can know which of the two that was returned by comparing <code>n</code> to the size of the one of the two structures (they are guaranteed to be different sizes). Something like this:</p> <pre><code>struct A { ... }; struct B { ... }; char buffer[1024]; int n = get_object(buffer, sizeof(buffer)); if (n == sizeof(A)) { // use it as A } else if (n == sizeof(B)) { // use it as B } else { // error occurred } </code></pre> <p>So here&#39;s my question. I&#39;m <strong>NOT</strong> using C++23, so I don&#39;t have <code>std::start_lifetime_as</code>. I assume it is UB to simply <code>reinterpret_cast</code>, correct?</p> <pre><code>if (n == sizeof(A)) { auto ptr = reinterpret_cast&lt;A *&gt;(buffer); // use ptr as A but is UB } else if (n == sizeof(B)) { auto ptr = reinterpret_cast&lt;B *&gt;(buffer); // use ptr as B but is UB } else { // error occurred } </code></pre> <p>I assume it&#39;s UB because as far as the compiler is concerned, it has no way of knowing that <code>get_object</code> is effectively, just <code>memcpy</code>-ing an <code>A</code> or a <code>B</code> into <code>buffer</code>, so it doesn&#39;t know that there&#39;s a valid object there.</p> <p>I believe this is essentially the problem that <code>start_lifetime_as</code> is trying to solve.</p> <p>So what&#39;s the best way to avoid UB? Do I just <code>memcpy</code> and hope that the compiler will optimize it out like this?</p> <pre><code>if (n == sizeof(A)) { A obj; memcpy(&amp;obj, buffer, sizeof(A)); // use obj as A } else if (n == sizeof(B)) { B obj; memcpy(&amp;obj, buffer, sizeof(B)); // use obj as B } else { // error occurred } </code></pre> <p>Or is there a better way?</p> <p>Bonus Question:</p> <p>I believe that it is valid to curry POD objects through <code>char*</code> buffers via <code>memcpy</code>. So if we happen to <strong>KNOW</strong> that the implementation of <code>get_object</code> looks something like this:</p> <pre><code>int get_object(void *buffer, size_t n) { if(condition) { if (n &lt; sizeof(some_a)) return -1; memcpy(buffer, &amp;some_a, sizeof(some_a)); return sizeof(some_a); } else { if (n &lt; sizeof(some_b)) return -1; memcpy(buffer, &amp;some_b, sizeof(some_b)); return sizeof(some_b); } } </code></pre> <p>Would that mean that the <code>reinterpret_cast</code> version of the code above would suddenly <strong>NOT</strong> be UB?</p> <p>More directly, does this mean that , if the API happens to fill the buffer via <code>memcpy</code>, then casting is valid but otherwise (like if it came via a <code>recv</code>) it isn&#39;t?</p> <p>This question is interesting to me because I don&#39;t see how the compiler could possibly know the difference on the usage end, and therefore would <strong>HAVE</strong> to treat them the same in both scenarios.</p> <p>What do you guys think? Because in principle, it seems no different from the compilers point of view than this:</p> <pre><code>char buffer[1024]; if(condition) { if (n &lt; sizeof(some_a)) return -1; memcpy(buffer, &amp;some_a, sizeof(some_a)); auto ptr = reinterpret_cast&lt;A *&gt;(buffer); // use ptr as A } else { if (n &lt; sizeof(some_b)) return -1; memcpy(buffer, &amp;some_b, sizeof(some_b)); auto ptr = reinterpret_cast&lt;B *&gt;(buffer); // use ptr as B } </code></pre> <p>Which, if I&#39;m understanding things correctly, is not UB. Or am I mistaken? Is it only valid if I were to <code>memcpy</code> from the buffer back into an object?</p> </div><!-- SC_ON --> &#32; submitted by &#32; <a href="https://www.reddit.com/user/eteran"> /u/eteran </a> <br/> <span><a href="https://www.reddit.com/r/cpp/comments/1jafl49/the_best_way_to_avoid_ub_when_dealing_with_a_void/">[link]</a></span> &#32; <span><a href="https://www.reddit.com/r/cpp/comments/1jafl49/the_best_way_to_avoid_ub_when_dealing_with_a_void/">[comments]</a></span>
