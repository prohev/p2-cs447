<!-- SC_OFF --><div class="md"><p>I have developed with c++ for about 4 years now, and the more I learn about the language, the more I grow to dislike it. The language is like an abusive partner that I keep coming back to because I still can&#39;t live without it.</p> <p>The main issues that I have lie in the standard library. The biggest issue that I have with the library is it&#39;s backwards compatibility baggage. The newer language versions have excellent features that make the language</p> <ol> <li>Compile faster</li> <li>More readable</li> <li>Easier to debug</li> <li>Faster to execute due to better compile time information</li> </ol> <p>The standard library doesn&#39;t make use of most of these features because of backwards compatibility requirements.</p> <p>The current standard library could be written with today&#39;s language features and it would be much smaller in size, better documented, more performant, and easier to use.</p> <p>Some older things in the library that have been superceded by newer fearures could just be deprecated and be done with.</p> <p>Personally, all features requiring compiler magic should be language features. All of &lt;type_traits&gt; could be replaced with intrinsic concepts that work much better.</p> <p>We could deprecate headers and have first-class support for modules instead.</p> <p>C++ would be my absolute favourite language without a doubt if all of the legacy baggage could be phased out.</p> <p>I would say that backwards compatibility should be an opt-in. If I want to start a new project today, I want to write c++23 or higher code, not c++98 with some newer flavour.</p> </div><!-- SC_ON --> &#32; submitted by &#32; <a href="https://www.reddit.com/user/AnTiExa"> /u/AnTiExa </a> <br/> <span><a href="https://www.reddit.com/r/cpp/comments/1j807qm/c_needs_stricter_language_versioning/">[link]</a></span> &#32; <span><a href="https://www.reddit.com/r/cpp/comments/1j807qm/c_needs_stricter_language_versioning/">[comments]</a></span>
